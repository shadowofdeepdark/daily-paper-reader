## 摘要
搭载 AI 助手的智能眼镜在日常生活中日益普及。然而，当前系统缺乏对用户内部认知状态的感知，因而无法在不了解认知负荷的情况下主动预判用户需求。现有的认知负荷评估方法要么依赖于难以应用于轻量级眼镜的传感器，要么使用基于眼动的模型，这些模型可解释性较差且需要针对具体任务进行微调，往往难以在个体间泛化。我们提出 GazeMind，一种基于注视引导的大语言模型（LLM）代理框架，用于在智能眼镜上进行认知负荷评估。该框架将眼动追踪数据编码为结构化表示以供 LLM 推理，并提供具有可解释性的认知负荷预测。重要的是，GazeMind 通过一种新颖的任务引导推理方法，无需对 LLM 进行微调即可在不同场景中泛化，并通过结合用户特征与历史参考实现个性化自适应。为支持评估，我们引入了 CogLoad-Bench，这是迄今最大的基于注视的认知负荷数据集，包含 152 名参与者、超过 40 小时的多模态数据，以及跨受控与真实任务的 10,000+ 条实时标注。实验结果表明，GazeMind 实现了当前最先进的性能，在所有指标上相比基线提升超过 20%。

## Abstract
Smart glasses with AI assistants are increasingly used in daily life. However, current systems lack awareness of the user's internal cognitive state, leaving them unable to proactively anticipate users' needs without access to cognitive load. Existing methods for assessing cognitive load either rely on impractical sensors for lightweight eyewear or utilize eye gaze-based models that suffer from poor interpretability, and require task-specific fine-tuning, often failing to generalize across individuals. We propose GazeMind, a gaze-guided LLM agent framework for cognitive load assessment on smart glasses. It encodes eye-tracking data into structured representations for LLM-based reasoning and provides interpretable cognitive load predictions. Importantly, GazeMind generalizes across scenarios without LLM fine-tuning through a novel task-guidance reasoning approach and achieves personalized adaptation by incorporating user-specific characteristics and historical references. To support evaluation, we introduce CogLoad-Bench, the largest gaze-based cognitive load dataset with 152 participants, 40+ hours of multimodal data, and 10K+ real-time annotations across controlled and real-world tasks. Experiments show that GazeMind achieves state-of-the-art performance, outperforming baselines by over 20% across all metrics.

## 二、方法论：GazeMind 框架及技术细节

### 1. 总体框架
论文提出 **GazeMind** ——一个结合 **眼动数据 + 大语言模型（LLM）推理** 的认知负荷评估架构，由四个功能模块构成：

1. **Temporal Gaze Encoding (TGE)**  
   - 将连续原始眼动信号（90 Hz）转换为认知科学解释性的时间特征表，包括：  
     - 注视持续时间、扫视持续时间、扫视幅度、注视比例、扫视比例、眨眼次数、瞳孔大小。  
   - 通过 Z-score 标准化并构造成结构化 Markdown 表格供 LLM 解析，从而捕捉时序趋势（如瞳孔持续增大）。
   - 该表示使 LLM 可自然理解时序变化，而非单一瞬时值。

2. **Task-Guidance Reasoning (TGR)**  
   - 针对不同任务（阅读、游戏等），为 LLM 生成任务特定推理规则。  
   - 规则生成流程：
     - 对任务内标注数据做分层统计（均值、标准差、四分位数）。
     - 将这些统计特征输入 LLM，让其生成结构化规则：找出最具区分性的特征、方向关系及阈值。
   - LLM 在推理时选择相应任务规则，保证可解释的任务适应性。

3. **Adaptive User Profile Calibration (AUP)**  
   - 解决个体差异：通过聚类将用户划分为三类 ——  
     - **High-Reactor**：瞳孔大且敏感。  
     - **Low-Reactor**：眨眼少、瞳孔变化弱。  
     - **Restless**：眨眼频率高、注视不稳定。  
   - 新用户仅需短校准任务即可确定个人档案，并在推理时调整特征解释（例如，Low-Reactor 用户的小变化仍可能表示高负荷）。

4. **Cognitive Retrieval-Augmented Generation (CogRAG)**  
   - 检索数据库中相似的历史样本作为“在上下文学习 (ICL)”参考。  
   - 相似性度量：对每个特征计算 **均值、标准差、时间趋势斜率** 并形成统计向量，使用欧式距离匹配。  
   - 检索得到的参考样本（同任务+同类型用户）与当前特征表一起输入 LLM，用于对比推理。  

### 2. 推理流程
最终推理将上述四模块信息整合入一个 LLM 查询：
> 输入：时序特征表 + 任务规则 + 用户档案 + 检索参考样本  
> 输出：认知负荷等级（低 / 中 / 高）及自然语言解释。

这一设计避免传统训练和微调，完全基于上下文提示实现任务泛化与个性化。

## 三、实验设计

## 七、优点与创新亮点

1. **融合 LLM 与生理信号的创新性架构**：首次在可穿戴设备场景中使用 LLM 解释眼动信号。

4. **检索增强推理**（CogRAG）：高效且无需密向量嵌入，支持实时运行。
